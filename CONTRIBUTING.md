# Contributing

Thank you for helping keep Awesome Personal CRM useful, current, and fair.

## What We Accept

An app entry must meet all of these criteria:

- It helps an individual remember, organize, or maintain personal or professional relationships. A sales-only CRM is outside this list's scope.
- It is actively maintained. For open-source projects, the default evidence is a commit or release within the last 12 months. For proprietary products, the official product and support surfaces must be operational and show evidence of current maintenance.
- It has an official public URL with enough information to verify what the product does.
- Its description is one neutral sentence. State what it does without rankings, testimonials, unsupported superlatives, or pricing claims that can quickly become stale.
- Its open-source or proprietary status is labeled accurately.

Competing products are explicitly welcome, including products that compete with Ember. Inclusion is based on scope, maintenance, and verifiable information, not affiliation.

Methods, portability resources, and articles should be directly useful to people building or maintaining a personal relationship system. Prefer primary sources for standards, legal rights, and platform-specific export instructions. Vendor-authored material is accepted when its source is clear and the description remains neutral.

## Pull Request Process

1. Search the list and open pull requests to avoid duplicates.
2. Add one entry per pull request unless several links are part of one correction.
3. Keep the existing alphabetical order within the relevant section.
4. Use the format `- [Name](https://example.com/) - Description.` and link to the official source when one exists.
5. Do not add tracking parameters, referral codes, URL shorteners, or affiliate links.
6. Explain how the entry meets the scope and maintenance criteria in the pull request description. Include the latest release or commit date for an open-source app.
7. Run `npx awesome-lint` from the repository root and resolve relevant errors.
8. Confirm that you have disclosed any employment, ownership, sponsorship, or other affiliation with the submitted product.

Maintainers may edit a description for neutrality, request evidence of maintenance, move an entry to a more accurate section, or remove an entry that is abandoned or no longer in scope. A removal is not a judgment on product quality.

## Corrections and Removals

Open a pull request for ordinary corrections. For a broken link, discontinued product, security concern, or factual issue that needs discussion, open an issue with the source and the proposed change.
